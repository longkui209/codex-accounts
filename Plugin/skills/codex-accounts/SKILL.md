# Codex 账号切换

使用本插件 `codex_accounts` MCP 服务器提供的工具；宿主可能为工具名称增加前缀。不要用终端复制、编辑或输出真实认证文件。

## 账号入口

0.14.0 面板顶部提供简体中文、繁体中文、英语、日语、韩语、西班牙语、法语、德语、葡萄牙语和俄语。用户选择只调用 app-only `accounts_set_language`，偏好按 Windows 当前用户加密保存；不应让模型代为修改账号以测试语言。显示语言不翻译账号备注、邮箱或官方数据，也不更改模型、额度、自动轮换或待确认操作。普通启动与切换方式默认折叠在「设置与启动」，帮助默认折叠；仅显示版本或连接状态不能代替真实请求完成证明。面板更新不需要替换正在运行的 Windows 启动组件。

本插件 0.5.0 声明了全局侧栏和会话面板 MCP App 入口。当前桌面实现默认把自定义全局入口放在侧栏“探索 / Explore”中；用户加载后选择“Codex 账号切换”，可在侧栏自定义中固定它。不要把发送聊天指令当作用户必须执行的步骤。工具列表包含入口及完整面板显示声明仅证明协议可加载，不能声称在用户桌面上已看见按钮，实际呈现必须人工确认。

- 用户要求打开面板：调用 `accounts_panel`。只有支持 MCP Apps 的宿主会显示内嵌账号卡片。没有组件时，根据工具返回的脱敏列表在对话中列出账号和可用操作；不要声称已修改 Codex 原生账号菜单。
- 查看账号：`accounts_list`；查看已有待切换：`accounts_pending_status`；查看已启动的手动登录：`accounts_login_status`。这些只读工具可用于确认状态。
- 刷新套餐和额度：`accounts_refresh_usage({force:true})` 查询所有已保存账号的官方套餐、额度窗口、重置卡次数及逐张到期时间，不执行模型推理、不使用重置卡、不切换账号。面板打开时查询并每分钟自动刷新；界面隐藏时暂停。失败保留上次结果并标记过期，缺失额度或次数不是零。
- `resetCredits.availableCount` 是官方总次数，不能用 `cards.length` 代替；详情可能只返回部分卡片。`expiryKnown=false` 是到期时间未知；只有明确 `expiryKnown=true` 且 `expiresAtUtc=null` 才表示官方未设到期时间。不要猜测固定有效期或将其当作订阅账单到期日。
- 使用重置卡仅通过面板的「使用此卡 → 确认使用 1 张」，显示并绑定具体账号、卡片、到期时间。`accounts_prepare_reset`、`accounts_use_reset` 是 app-only 控件，不向模型提供；不要通过终端代为兑换，也不要为验证功能消耗真实卡。查询、打开面板和刷新不构成使用重置卡的授权。
- 结果未知时保留 `resetPending`，用户可在面板核对同一次操作，复用原确认及幂等标识；禁止自动重试、改用另一张卡或另一账号。只有官方明确 `reset` 才报告本次新重置完成；`already_redeemed` 是原操作已处理，`nothing_to_reset`、`no_credit` 不能称为新重置成功。
- `accounts_list` 中的 `planSource=server` 才表示套餐来自官方用量查询；`cached` 是旧登录缓存标签。优先结合 `usage.updatedAtUtc`、`usage.stale` 和 `usage.status` 判断时效，不能将备注“10X”或旧 Pro 标签视为当前服务端套餐。套餐或目录查询成功也不是模型请求完成证明。
- 保存当前账号：在用户明确要求保存当前登录并给出名称后，调用 `accounts_capture_current({label})`。
- 添加账号：在用户要求登录新账号并给出名称后，调用 `accounts_begin_login({label})`。官方登录页面由本机组件打开；密码、验证码及登录选择由用户本人在浏览器完成。使用 `accounts_login_status` 查询完成状态。
- 重命名：从 `accounts_list` 解析账号标识后，调用 `accounts_rename({account_id,label})`。
- 移除账号：通过面板的「移除 → 确认移除」，仅移除指定本机保存记录，保留加密副本。`accounts_remove` 与 `accounts_restore_removed` 仅向面板开放，模型不要通过终端代为移除。用户没有指明目标账号时不得实际移除任何真实记录。
- 当前使用的订阅需先切换到其他账号再移除；桌面当前登录同样受保护。运行中请求、待完成账号操作、未确认重置卡操作或旧主机不支持原子保护时拒绝移除。完成后可点击「撤销上次移除」恢复保存记录；不能用旧副本覆盖后来重新添加的凭据，桌面认证与订阅选择不随撤销改变。

`label` 必须是 1 至 60 个字符。未提供名称时，仅询问该名称，不要求用户再次授权已经明确请求的动作。若多个账号同名，先用脱敏邮箱与订阅类型确认目标；不要猜测账号标识。

## 保留原生功能的订阅切换

0.13.1 用户明确要求整机所有 Windows 登录账户生效：机器级规则对匹配的客户端路径生效。已安装插件且已有个人账号库的用户使用自己的路由，未使用插件的用户保持普通原生启动；不跨 Windows 用户读取或共享凭据。这是登记范围和实现意图，多用户实际登录、原版图标和远程手机连接仍须分别核验。用户在当前会话明确要求开发/安装该整机组件时，可依其授权完成组件安装，不把面板控件限制解释为必须重复取得同一授权。

0.13.0 增加面板「普通启动」组件入口。安装需要一次 Windows 管理员确认；本机复制并逐文件核验已安装的官方运行文件，不在插件包分发官方资源。准备后等待用户正常退出客户端才登记精确路径启动规则，随后自动重开；不能强制退出、把等待安装或注册状态称为真实请求成功。`accounts_startup_status` 只读；`accounts_install_startup` / `accounts_uninstall_startup` 仅供面板明确确认，模型不得代替用户点击这两个控件。恢复只移除本组件精确归属的启动规则；运行中的文件保留。原厂更新后须核对当前安装路径，旧版本规则不能当作已覆盖新版。

0.13.0 同时修复并行会话轮换竞争：某一请求自动选择新账号后，其他在旧账号上收到明确额度拒绝、尚未输出的请求仍可独立核对候选并接续；非标准媒体类型中的同类明确错误也可以识别。普通限速、认证失败、已有内容或不完整服务端续接仍不跨账号重放。

面板提供两种明确选择。用户在真实耗尽状态验证 0.11.0 仍禁用发送：只修了初始额度判断，遗漏独立的 Work 额度判断。此前单个 `frontendAdapted=true` 和已有请求完成不能证明新消息可发。0.12.0 从专用入口启动时，通过继承的匿名管道适配两份经哈希审核的原生资源；必须同时核对 `live.nativeInput.initialQuotaAdapted`、`workQuotaAdapted` 及最新更新时间，旧标记/部分加载不得称为完整覆盖。Work 共用额度函数和云端消费者不改，只替换本地输入框消费者。

`workQuotaNativeBlocked`、`workQuotaEffectiveBlocked` 和 `workQuotaCheckedAtUtc` 为本地输入框运行时读回的非个人布尔诊断；null 表示尚未观察，不是 false。不改安装文件、不开放网络调试端口、不更换桌面身份，也不改原账号官方额度对象。仅对 host=local 生效，云端与远程、忙碌及权限等检查保留。不兼容、断连或额度未知恢复原判断。两份资源加载和合成按钮表达式通过仍不能替代用户实际灰按钮恢复及新消息完成证明。

「同步切换桌面登录」须由用户在面板选择具体账号并确认，app-only 的 `accounts_request_desktop_switch` 仅登记 15 分钟有效意图，当前登录不改。用户正常退出全部客户端后，从已更新的专用启动入口打开时，组件重新查询目标官方额度、核对原身份、备份并原子写入认证；不启动退出等待进程、不强制关闭客户端。`accounts_cancel_desktop_switch` 只取消匹配 ID 且尚未开始应用的意图。模型不能代用户调用这两个 app-only 工具。缓存 `completed` 仍不是原生登录、发送按钮或真实请求完成的证明。

名称、用户名与头像只由面板通过 app-only 的 `accounts_profile_details` 读取各保存账号登录时返回的可选资料，不是实时个人资料接口。缺失字段整项隐藏，不派生用户名、不伪造头像，不操作浏览器其他账号。普通账号列表不返回这些个人资料，模型不要代为输出或写入日志。原生登录与本地备注、账号展示资料始终分别处理。

先查看 `accounts_routing_status` 或 `accounts_list` 中的 `subscriptionRouting`。若未接入，提示用户完成任务并正常退出桌面后，从桌面「Codex（订阅切换）」启动；不要结束用户进程、修改模型设置或绕过实验性签名身份模式。

用户明确选择目标账号或在面板点击按钮后，从返回列表取得 `id`，调用 `accounts_select_subscription({account_id})`。有正在返回的请求时会拒绝；保持原选择，等待响应结束再由用户重试。不要自动换到其他账号。

成功只表示后续模型请求的订阅已选择，不表示真实请求已被服务端接受，也不表示桌面已登录为该账号。桌面登录、插件连接、语音、历史和笔记仍属于原账号。模型 ID、推理参数、请求正文及成功回复不被改写。认证失败按固定提示处理，不把失败请求换到其他账号重放。

用户可在面板开启「额度耗尽自动轮换」，默认关闭并加密保存。此开关的 `accounts_set_auto_rotation` 仅向面板开放，不能仅因用户讨论该功能便自动替其开启。开启后仅对明确的 HTTP 429 `usage_limit_reached`，或输出开始前的同类 SSE 拒绝，在转发层核对其他保存账号的当前额度与模型权限，再以同一请求原字节接续；桌面不会先收到中间的额度错误。请求完整上下文和工具结果保留，项目无需从头重跑。普通限速、认证失败、网络不明、服务端续接引用或已经产生内容的流不跨账号重放。不能把关闭错误提示当作轮换成功，每个候选只试一次，全部不可用时如实报告。此开关不授权自动使用重置卡。

保存当前账号始终保存原生桌面登录；不要把已选择的模型订阅误称为桌面登录。首次从专属入口启动后，切换订阅不需要重启桌面。

## 普通模式的退出后切换

用户明确选择目标账号时，先从 `accounts_list` 取得该账号 `id`，再调用 `accounts_request_switch({account_id,reopen})`。`reopen` 默认 `true`；用户要求不自动打开时传 `false`。

该操作登记一个有 10 分钟时限的本机待切换请求。提示用户结束正在运行的任务，正常退出所有 Codex / ChatGPT 桌面窗口和 Codex 后台。工作组件只会在检测到全部停止后执行；不能关闭、强杀客户端或中断任务。当前对话在登记请求后仍使用原账号。

用户要求取消时，调用 `accounts_cancel_switch`；取消未完成的新账号登录用 `accounts_cancel_login`。取消、重命名、保存、登录和发起切换都需要用户直接授权。查看状态不构成重新登录、再次切换或自动重试的授权。

## 真实结果

- `pending` / `waiting` 表示仍在等待退出；`completed` / `complete` 只表示磁盘认证缓存切换完成。登录是否被服务端接受，需要重新打开客户端后确认。
- `failed` / `expired` / `cancelled` / `canceled` 按工具给出的固定提示说明结果，不能宣称切换完成。超时或断连时先查询已有状态，不重复提交写操作。
- 不在对话、组件、日志或文件中显示令牌、原始认证 JSON、登录网址中的临时参数或验证码。工具返回的脱敏身份来源于本地缓存，不是服务端认证证明。
- 插件依赖本机 Windows DPAPI 和官方 Codex CLI；云端或不支持本地 stdio 的宿主不能执行本机切换。组件可选，文本工具仍是账号操作入口。
